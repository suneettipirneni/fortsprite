# Security remediation rollout

The code and lockfile changes need deployment before they protect production. The local verification environment uses a separate PostgreSQL database and simulated Epic responses; it does not modify existing production accounts.

1. Back up the target database using the provider's encrypted backup controls, and verify access is restricted. Keep `BETTER_AUTH_SECRET` unchanged during this rollout; the same secret is used for legacy session verification and version-1 OAuth ciphertext. A database export must not contain that secret.
2. Install the committed lockfile with `pnpm install --frozen-lockfile`. Run the package-local Drizzle migration command against the target database as usual. The new security controls reuse the existing rate_limit table and need no new SQL schema migration.
3. Pause sign-in/token-refresh traffic and stop old application instances. With the new source, target `DATABASE_URL`, and existing auth configuration, run `pnpm --filter @fortsprite/api auth:encrypt-tokens`. This encrypts legacy access/refresh tokens in batches under row locks. It is repeatable; it verifies already-encrypted envelopes and fails on unreadable ciphertext. It logs only account counts. Do not resume an older application version against the encrypted tokens.
4. Build and deploy the patched app, then resume traffic. Verify real Epic sign-in, token refresh, sign-out, local blocking, profile/collection updates, deletion, and current browser headers. Re-run the token command if old instances were accidentally permitted to write plaintext during rollout. Keep rollback builds encryption-compatible.
5. Expire or retire old plaintext database exports under the actual backup-retention policy. Encryption of current rows cannot remove tokens from historical backups. If an export was exposed, revoke affected credentials with Epic rather than relying on encryption after the fact.

The shared per-user budgets are 120 collection writes, 30 profile edits, 60 sharing grants, 120 privacy actions, and 10 deletion attempts per minute. Privacy actions have their own allowance, independent of discovery and other mutations. Rejected requests return 429 and Retry-After without extending the fixed window. Direct HTTP and server actions use the same Hono enforcement. Account deletion removes the user's application counters.

Hono limits application request bodies to 16 KiB and auth bodies to 32 KiB, checking actual streamed bytes even for internally constructed Requests with a supplied Content-Length. Next server actions also have a 16 KiB limit. The standalone debug API binds only to 127.0.0.1. Public deployment uses the documented Vercel origin/IP boundary; a different reverse proxy needs explicit trusted-IP review.

Browser policy denies framing, objects and foreign script origins and restricts form targets and base URLs. It permits inline hydration scripts/styles because Cache Components and partial prerendering cannot use request nonces for static shells. It does not claim to be a strict nonce CSP. Production omits unsafe-eval; development allows it for React diagnostics. External font styles/files are limited to rsms.me; fetch access is limited to its /inter/ path so accessibility tools can inspect the existing stylesheet. The Next production testing API can only be enabled by the existing local .next-instant harness with a test database and the fixed localhost test origin; Vercel is rejected.

The scoped Drizzle override removes an unused @esbuild-kit/esm-loader dependency from 0.31.10, whose published runtime bundles tsx instead. This avoids forcing a breaking esbuild version into the old loader. Remove the override when an upstream release removes that dependency. Verify Drizzle migration/config loading whenever changing this exception. The other overrides constrain vulnerable transitive versions to patched compatible releases; re-run the complete audit before removing them.

Infrastructure controls still require the deployment owner to verify actual database TLS, least-privilege roles, backup access/retention, firewall/rate policies and secret rotation. These were not confirmed defects in the code audit, and no infrastructure state was changed. Epic grant revocation is separate from local account deletion; deleting local credentials does not revoke the Epic-side consent grant. Users can revoke that grant in Epic's account controls.
